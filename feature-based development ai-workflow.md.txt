# Standard Workflow for New Features

## ⚠️ CRITICAL RULE

**NEVER implement directly without first:**
1. Creating a feature document
2. Showing the implementation plan
3. Receiving confirmation

This rule applies ALWAYS, without exception!

---

## Prompt Template for AI (Cursor/Claude)

```
CONTEXT:
- Read docs/implementations/overview.md for project basics

TASK:
[Describe your feature requirement here]

PROCEDURE:
1. Analyze the requirement

2. Create feature document:
   - Use docs/templates/feature-template.md as basis
   - Save under docs/implementations/[feature-name].md

3. Fill out feature document completely:
   - Status: Planned
   - Metadata (Priority, Dependencies)
   - Overview
   - Technical Details
   - Implementation Plan (detailed!)
   - Code Structure
   - Open Questions

4. Update overview document:
   - docs/implementations/overview.md (feature table only!)

5. Show me the feature document for confirmation

6. After my confirmation:
   - Implement according to implementation plan
   - Update status in feature document to "Implemented"
   - Add key interfaces/types to the document

IMPORTANT:
- No implementation without confirmed feature document
- Overview file stays compact (only general concepts + feature list)
- All feature details belong in the feature document
```

### Scenario 2: Extending an Existing Feature

```
CONTEXT:
- Read docs/implementations/user-authentication.md (existing feature)
- Read docs/implementations/overview.md

TASK:
Extend authentication with:
- 2FA with TOTP
- OAuth2 integration
- Biometric authentication

PROCEDURE:
1. Open docs/implementations/user-authentication.md

   - New phase for extensions
3. Update "Change History"
4. Show me the changes for confirmation
5. After confirmation: Implement
6. Update code structure in document
```

### Scenario 3: Bug Fix

```
CONTEXT:
- Read docs/implementations/overview.md
- Find the affected feature document

Bug in feature: [Feature-Name]
Problem: [Brief description of the bug]

PROCEDURE:
1. Identify the feature document
2. Read the feature document completely
3. Analyze the problem
4. Fix the bug
5. Update change history in feature document:
   - YYYY-MM-DD: Bug fix - [Description]
```

### Scenario 4: Update Documentation After Implementation

```
Implementation is complete.

TASK: Update documentation
1. Find the corresponding feature document in docs/implementations/
2. Update feature document:
   - Status → "Implemented"
   - Add key interfaces/types
   - Update change history
3. Update overview:
   - docs/implementations/overview.md
   - Change feature status in table
```

## Tips for Effective Prompts

### ✅ DO's
- **Be specific:** "Implement user login with JWT" instead of "Do auth"
- **Give context:** "Extend existing feature X" instead of "Do Y"
- **Ask for plan:** Always have the plan shown first
- **Reference docs:** "Read overview.md" for better context

### ❌ DON'Ts
- **Don't be vague:** "Make it better"
- **Don't skip context:** "Create component X" without reference to structure
- **Don't implement directly:** Without creating a feature document
- **Don't clutter overview:** Only general concepts + feature list in overview

## Standard AI Follow-up Questions

The AI should ask the following questions for unclear requirements:

1. **For unclear dependencies:**
   ```
   "Which existing features are required?
   (See docs/implementations/overview.md for list)"
   ```

2. **For missing priority:**
   ```
   "What priority does this feature have? (High/Medium/Low)"
   ```

3. **For unclear scope:**
   ```
   "What specific functionalities should this feature include?"
   ```

## What Goes Where?

### In `docs/implementations/overview.md`:
✅ Technology stack  
✅ Architecture overview  
✅ Common concepts  
✅ Conventions & best practices  
✅ **Feature list with status** (table)  
❌ Feature details (belong in feature documents)  
❌ Implementation details (belong in feature documents)  

### In Feature Documents:
✅ Complete feature description  
✅ Implementation plan  
✅ Code structure  
✅ Technical details  
✅ Open questions  
✅ Change history
