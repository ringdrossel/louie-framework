# Framework Changelog

Internal version log for the LOUIE framework. Tracks meaningful changes to the framework itself — not user project artifacts. Entries here inform what `louie-update-framework` users see when they pull a new version.

Format: reverse chronological, date + short description + affected areas.

## Unreleased

- **Per-project roadmap added** — new artifact `_LOUIE-output/roadmap.md` for capturing pre-feature-folder ideas, with a `louie-roadmap` command for adding and promoting entries. Fills the gap between `louie-ideate` (chat-only, ideas evaporate) and `louie-feature` (full chain, full commitment) — captured ideas persist with the lightest possible schema (ID + Title + Created + Source + Notes; optional Effort; never Priority/Owner/Dependencies, which belong on a feature doc). v1 subcommands: `add` and `promote`; bare call prints the current roadmap. No agent owns it (same as `runbook.md`) — the command writes directly. `louie-ideate` now ends with a three-bucket sort (pursue now / save to roadmap / drop) instead of dumping ideas into chat. `louie-feature` accepts `--from-roadmap <id>` to seed Tom with a captured entry; on success, the entry moves from `## Captured` to `## Promoted` with a back-link to the feature folder (auditable trail). `roadmap.md` is lazy-created on first `add` — no init-script bootstrap, no migration step, existing LOUIE projects gain the feature automatically. New files: `_LOUIE_/commands/louie-roadmap.md`, `_LOUIE_/templates/roadmap-template.md`, `_LOUIE-internals/roadmap.md` (design rationale). Updated: `louie-ideate`, `louie-feature`, `_LOUIE_/agents/muse.md` (small Output Format note), `CLAUDE.md`, `README.md`, `_LOUIE_/workflow/ai-workflow.md` (new Scenario 8), `_LOUIE_/setup/project-setup.md`, all six init scripts, `feature-template.md` and `implementations/overview.md` scaffold (one-line cross-references). BACKLOG entry "Tom standalone" annotated as partially absorbed. No changes to Tom, Sophie, Nina, Max, Ava, Leo, or any chain command (`louie-bugfix`/`louie-extend`/`louie-update`/`louie-test`/`louie-review*`/`louie-doc`/`louie-recipe`/`louie-import`/`louie-migrate`/`louie-update-framework`/`louie-setup`).
- **Reviews are session-time only — no standalone review files** — clarified the storage convention for code reviews. Max produces findings in chat; outcomes fold into the existing per-feature artifacts (Change History on `feature.md`; optional ADR on `decisions.md`; `louie-bugfix` flow for real bugs). Updated `_LOUIE_/agents/reviewer.md` (new "Storage convention" block at top of Output Format), `_LOUIE_/commands/louie-review.md` (added explicit "do not write a separate review file" + a "Record the outcome" step), `_LOUIE_/commands/louie-review-doc.md` (in-chat-only constraint), and `_LOUIE_/workflow/agent-handoffs.md` (Max's Produces cell rewritten). The previous wording "Review comments on feature doc" was ambiguous and led at least one downstream AI to invent its own review-file pattern. The framework optimizes for minimum viable artifacts; review files would scale badly (every feature accumulates them, stale risk, duplicates Change History) and don't merit a new artifact category.
- **Per-feature folder layout (BREAKING)** — restructured `_LOUIE-output/` so each feature lives in its own folder: `_LOUIE-output/implementations/<feature>/feature.md` + `requirements.md` + `decisions.md` (created when needed) + `bugfixes/<YYYY-MM-DD>-<slug>.md`. Top-level `_LOUIE-output/requirements/` removed (per-feature `requirements.md` lives inside the feature folder). New top-level `_LOUIE-output/bugfixes/overview.md` is the cross-project bug-fix index; cross-cutting fixes that touch multiple features live at `_LOUIE-output/bugfixes/<YYYY-MM-DD>-<slug>.md`. `implementations/overview.md` slims to a one-line-description index that respects lazy-loading. Direction (universal — no conditional/threshold switching) and decisions locked on AI-efficiency criterion in `_LOUIE-internals/scaling.md`.
- **Migration command added** — new `louie-migrate` command performs the one-way restructure for existing LOUIE projects: pre-flight git-clean check, per-feature `git mv` (preserves history), orphan-requirements handling, cross-reference rewrite across `architecture.md`/`tech-stack.md`/`runbook.md`/feature docs, `bugfixes/overview.md` bootstrap, `requirements/` cleanup. Idempotent. Migration is offered automatically by `louie-update-framework` when it detects the old flat layout. No backfill of bug fixes from feature-doc Change History (heuristic-noisy data is worse than incomplete data).
- **New templates** — `bugfix-template.md` (per-fix output doc with symptoms/root cause/fix/regression test/runbook update sections), `decisions-template.md` (lightweight ADR with stacked entries; split-when-needed at ~10 ADRs), `bugfixes-overview-template.md` (cross-project fix index). `feature-template.md` updated with layout note and Bug Fixes section pointing at `bugfixes/`. `bugfix-prompt-template.md` rewritten for the new layout.
- **All commands updated for the new layout** — `louie-setup`, `louie-import`, `louie-feature`, `louie-extend`, `louie-update`, `louie-bugfix`, `louie-recipe`, `louie-doc`, `louie-review`, `louie-review-doc`, `louie-test`, `louie-ideate`. `louie-bugfix` now creates per-fix docs and updates the cross-project index. `louie-extend` appends to the feature's existing `requirements.md` rather than creating sibling files.
- **All chain agents updated** — Tom writes to `<feature>/requirements.md`; Sophie reads requirements from per-feature folders; Nina writes per-fix docs; Max checks bugfix-doc + index coverage; Ava reads bug-fix docs for regression tests; Leo + Ivy path references updated.
- **`louie-import` produces the new layout** — both cold and v1-docs imports create per-feature folders. Refuses to run when an old flat layout is detected, pointing the user at `louie-migrate` instead.
- **Top-level docs and init scripts** updated to reflect the new layout (CLAUDE.md, README.md, project-setup.md, ai-workflow.md, agent-handoffs.md, six init scripts). Init-script Key Files sections call out per-feature folders and `bugfixes/overview.md` explicitly.
- **`_LOUIE-output/` skeleton** — top-level `requirements/` removed; new `bugfixes/overview.md` (from template) added; `implementations/overview.md` rewritten as a slim index with layout notes.
- **Import command added** — new `louie-import` command for retrofitting LOUIE onto projects that already have source code. Auto-detects two modes: **cold** (no prior docs — Sophie scans manifests/entry points/folder shape to infer architecture, tech-stack, runbook; Tom fills gaps via short interview) and **v1-docs** (translates `docs/implementations/overview.md` + per-feature `*.md` siblings — the v1 precursor schema — into LOUIE format). Reuses Tom + Sophie; no new agent. Discovered features written with status `Implemented` (trust-as-truth — running code is the source). Documentation pass only — never modifies source. Architecture confirmation gate applies. Init scripts (`claude/cursor/codex × sh/bat`) detect existing projects via manifest files, `src/app/lib` directories, or v1 docs, and recommend `louie-import` after install. Registered in this repo's `CLAUDE.md`, `README.md`, `_LOUIE_/workflow/ai-workflow.md` (new Scenario 6), `_LOUIE_/setup/project-setup.md`, and all six init scripts. Design rationale in `_LOUIE-internals/import.md`.
- **Internals docs scaffolding** — added `_LOUIE-internals/` with `README.md`, `core.md`, `recipes.md`, `CHANGELOG.md`. Not distributed. Added pointer from this repo's `CLAUDE.md`.
- **Recipe system designed** — design locked in `recipes.md`. See that file for dispatcher rules, folder layout, and name-resolution algorithm.
- **Recipe system implemented** — added `_LOUIE_/commands/louie-recipe.md` (dispatcher) and `_LOUIE_/recipes/README.md` (authoring guide). Registered `louie-recipe` in this repo's `CLAUDE.md`, `README.md`, `_LOUIE_/workflow/ai-workflow.md`, and all six init scripts (claude/cursor/codex × sh/bat).
- **First recipe: `admin:settings`** — DB-backed settings store with section+key composite, typed values (string/number/boolean/json), full admin UI (table, section filter, type-ahead search, edit dialog, delete confirm). Stack-agnostic — server-side search required when an API exists. Added `_LOUIE_/recipes/admin/README.md` + `_LOUIE_/recipes/admin/settings.md`.
- **Runbook system added** — new canonical output `_LOUIE-output/runbook.md` for runtime/operational content (deployment model, ports, commands, env vars, gotchas, debugging). Distinct from architecture (design-time) and tech-stack (build-time). Filled a category-wide gap in AI dev frameworks (verified vs. SpecKit and BMAD V4/V6). Six-section template at `_LOUIE_/templates/runbook-template.md`. Lifecycle: Sophie creates at setup, Nina appends during feature work and bugfixes (mandatory for bugfixes — they're the highest-value entries), Max verifies during review. No new agent. Updated `architect.md`, `coder.md`, `reviewer.md`, all relevant commands (`louie-setup`, `louie-feature`, `louie-extend`, `louie-bugfix`, `louie-review`, `louie-review-doc`), workflow doc, all six init scripts, README, project-setup, this repo's CLAUDE.md. Design rationale + comparison to BMAD/SpecKit in `_LOUIE-internals/runbook.md`.
- **`louie-update-framework` gaps closed** — added `_LOUIE_/recipes/` to the update list (was missing — recipes were added after this command was written). Added a new step that checks for newly-required `_LOUIE-output/` artifacts (e.g. `runbook.md`) and offers to bootstrap them rather than silently creating files.
