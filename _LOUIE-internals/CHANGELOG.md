# Framework Changelog

Internal version log for the LOUIE framework. Tracks meaningful changes to the framework itself — not user project artifacts. Entries here inform what `louie-update-framework` users see when they pull a new version: the command reads this file from the pulled clone and prints the sections between the project's `_LOUIE_/VERSION` and the pulled one.

Format: reverse chronological. New work lands under `## Unreleased`; a release moves that content under a `## <version> — <date>` header and sets `_LOUIE_/VERSION` to match (see `core.md` § Release Process — the consistency lint enforces that the newest release header equals `_LOUIE_/VERSION`).

## Unreleased

- **`update-all.sh`: regenerate marker-less context files; three-bucket report.** Context files predating the closing `<!-- /LOUIE-FRAMEWORK -->` marker were skipped as unsafe. On a real fleet the one project that hit the case had a context file that was *entirely* the LOUIE block — nothing to protect, and the guard just left it stale. Early init scripts append their block, so marker-to-EOF is framework content by construction; it is now regenerated with a reported `.louie-bak` backup. The closing report also split into three buckets — **notes** (already handled, no action), **optional** (canonical artifacts the assistant can bootstrap), and **needs the assistant** (only what the script genuinely cannot do) — replacing a flat list that told the user to run `louie-update-framework` everywhere and so undercut the script's whole point. When the last bucket is empty it now says so.
- **`update-all.sh` applies by default; `--dry-run` previews.** The original inversion (`--apply` opt-in) treated the refresh as dangerous. It isn't: `_LOUIE_/` is framework-owned and regenerable from any ref via `install.sh --force --version`, and `_LOUIE-output/` is never touched, so the operation is near-fully reversible. Making the safe-and-common case the default removes a flag from the path people actually run.
- **`update-all.sh`: refresh everything except the framework itself.** The original blocker set (pre-versioning installs, major version gaps, flat layout, dirty trees, non-git dirs) refused 15 of 24 projects on a real fleet, and the refusals were mostly wrong. The pre-versioning block was circular — it deferred to `louie-update-framework`'s "filesystem-based migration detection," but the only thing that detection looks for is the flat layout, which this script already tests directly; exactly one of the 15 had it. Now only two conditions stop an update: the directory isn't a LOUIE project, or it is the framework's own source repo. This is safe because `_LOUIE_/` is framework-owned and regenerable while `_LOUIE-output/` is never touched — a refresh has almost nothing irreversible to destroy. The dirty-tree check narrowed from "any uncommitted change" to `git status -- _LOUIE_`, the only path the update overwrites: a project with mid-edit *application* code was being skipped over changes a framework refresh cannot reach. Everything formerly blocking is now reported for follow-up (flat layout → `louie-migrate`, major version gap → migrations, missing `runbook.md` / `roadmap.md` → assistant bootstrap, uncommitted `_LOUIE_/` edits → the one genuinely irreversible loss, warned before it happens).
- **`update-all.sh` guards: never self-update, never downgrade.** A maintainer's checkout of this repo has a `_LOUIE_/` directory and so looks like an installed project to a filesystem scan — but refreshing it would `rm -rf` the source tree and replace it with the last *published* copy, reverting unreleased work. Detection keys on `_LOUIE-internals/` (repo-only, never distributed) plus a root `install.sh`. The bug stays latent while the repo's `VERSION` matches the published one and arms itself precisely during a release cut, when `VERSION` is bumped locally before the tag is pushed. The same fix replaced the bare `local = latest` equality check with an ordered semver comparison: equality treats "ahead" and "behind" alike, so any project ahead of the published release was silently downgraded.
- **`update-all.sh` — bulk framework refresh across many local projects.** Scans directory trees for LOUIE projects, reports each one's version against the latest, and with `--apply` refreshes the ones that are safe. Deliberately partial: it does the mechanical part (replace `_LOUIE_/`, refresh the context-file block, re-run init scripts) and refuses the judgment parts, reporting them instead — major version gaps (where migrations live), pre-versioning installs, the old flat `_LOUIE-output/` layout, dirty or non-git working trees. **The triage report is the primary output**; a skipped project is a correct result, not a failure. Dry run is the default. Solves one problem `louie-update-framework` can't reach on its own: init scripts skip the context-file section when the LOUIE marker is present, so framework changes to the `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` block never land in existing projects — the script splices a freshly generated block between `<!-- LOUIE-FRAMEWORK -->` and `<!-- /LOUIE-FRAMEWORK -->`, preserving everything outside the markers, and reports (rather than guesses at) files predating the closing marker. Also documents a distribution gotcha: `.gitattributes` marks `_LOUIE-internals/ export-ignore`, so the changelog is absent from GitHub tarballs and must be fetched separately from `raw.githubusercontent.com` — `louie-update-framework` is unaffected because `git clone` ignores `export-ignore`. Design: `_LOUIE-internals/install.md` § Bulk update.

## 1.1.0 — 2026-07-31

- **One-liner install — `install.sh` + `install.ps1` at the repo root.** `curl -fsSL .../install.sh | bash -s -- claude` replaces "copy two directories out of the repo, then find the right init script" with a single command. Design: `_LOUIE-internals/install.md`. Three decisions carry the design. **(1) Allowlist, never denylist** — only `_LOUIE_/` and `_LOUIE-output/` are copied, so anything new at the repo root stays out of user projects by default; a denylist would have started shipping `_LOUIE-internals/` the day it was added, which is exactly how the old copy-it-yourself instructions went stale. **(2) `_LOUIE-output/` is seeded per file, never wholesale** — the directory holds user work, so an existing `implementations/overview.md` with real features survives any re-run, matching the rule `louie-update-framework` already follows. **(3) Fully non-interactive** — under `curl | bash` stdin *is* the script, so a `read` would consume its own source text; every choice is a flag or an autodetect, and `/dev/tty` is documented as the escape hatch if a prompt ever becomes unavoidable. Guards refuse to overwrite an existing install and point at `louie-update-framework` (whose version-gated migrations a blind overwrite would skip); `--force` overrides. Default ref is `main` with `--version` / `LOUIE_VERSION` for pinning — a hardcoded default tag rots at every release cut that forgets to bump it, which this repo had already demonstrated. Tool autodetection mirrors `louie-update-framework` step 1's marker set and defaults to Claude Code. README, QUICKSTART (EN + DE), and `project-setup.md` now lead with the one-liner; the manual copy stays as the offline fallback. The consistency lint does not cover the installers (they register no commands) — sh/ps1 parity is a manual review item, noted in `install.md`.
- **Version/tag re-sync.** `_LOUIE_/VERSION` had sat at `1.0.0` across the `v1.0.1`–`v1.0.3` tags, and the eight entries below never got a release header. Because `louie-update-framework` compares local `VERSION` against pulled `VERSION` and stops at "already current" when they match, downstream projects on 1.0.0 pulling v1.0.3 content were told they were up to date and shown no changelog delta — those releases shipped invisibly. This release rolls all of it up under one header and sets `VERSION` to `1.1.0` so the delta reporting works again.

- **New recipe section `desktop/` + recipe `desktop:app-icon`.** Generalizes an Electron-on-Linux workflow debugged end to end in a real AppImage/KDE project into a toolkit-neutral recipe covering **Electron and Qt/C++**. Core claim: an application icon lives in **four independent surfaces** — (1) packaging / `.desktop` entry (`build.linux.icon` vs CMake `install()` + `linuxdeploy`), (2) the in-code window icon (per-`BrowserWindow` `icon:` vs one app-wide `QGuiApplication::setWindowIcon()`), (3) in-app usages (notifications/About), and (4) the DE's installed/extracted copies under `.../icons/hicolor/{256x256,512x512}/apps/` that KDE writes **once** on AppImage integration and never refreshes. Surfaces 3–4 are toolkit-agnostic; only 1–2 differ, so the recipe carries a surface×toolkit table rather than branching throughout. A naive "replace the PNG and rebuild" fixes at most one surface. **Display-server axis** treated as first-class: under X11 the in-code icon applies; under Wayland there is no xdg-shell window-icon protocol, so the compositor resolves the icon from an installed `.desktop` entry via `app_id` — making `setDesktopFileName()` / `app.setDesktopName()` a hard requirement and surfaces 1+4 the only ones that matter. Established pattern: one canonical `assets/icons/icon.png` (1024×1024 RGBA, artwork trimmed to ≥95% of canvas) referenced by surfaces 1–3, plus a repeatable normalize → overwrite → rebuild → refresh-DE-copies-and-caches → relaunch procedure with `cmp`-based verification. Pitfalls encoded, all actually hit: **packaged asset paths that only resolve in dev** (Electron's asar bug — `path.join(__dirname, '../../assets/…')` resolves inside `app.asar` while `extraFiles` assets sit next to the executable; Electron shows *no* window icon and the WM falls back to the stale desktop-entry icon, which misreads as a cache problem — fix is the `app.isPackaged` branch; the Qt analogue is a build-tree-relative path, sidestepped entirely by `.qrc`/`:/icons/icon.png`), assuming X11 semantics on Wayland, non-full-bleed source artwork (~75% fill renders visibly smaller than neighbouring taskbar icons; normalize with `magick -trim +repage -resize -background none -gravity center -extent`, expect one optical iteration with the user), and the DE cache flush (`rm ~/.cache/icon-cache.kcache`, `gtk-update-icon-cache -f -t`, `kbuildsycoca6`, plasmashell restart; a running app keeps its old window icon until relaunch). Variations cover `.ico`/`.icns`, full hicolor ladder, scalable SVG, `.deb`/`.rpm`/Flatpak, GNOME, a scripted swap, and tray icons. New section rather than `build/` — that section is scoped to build-time value derivation baked into gitignored artifacts, which this isn't. Added: `_LOUIE_/recipes/desktop/README.md`, `_LOUIE_/recipes/desktop/app-icon.md`.
