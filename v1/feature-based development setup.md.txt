# Project Setup with Feature-Based Documentation

## Overview
This guide helps you set up a new project directly with a feature-based documentation structure.

## Procedure

### Phase 1: Create Basic Structure

Create the following folder structure:

```
project-name/
├── docs/
│   ├── ai-workflow.md
│   ├── implementations/
│   │   └── overview.md
│   └── templates/
│       └── feature-template.md
├── src/
└── README.md
```

#### 2. Create `docs/ai-workflow.md`:

```markdown
# Standard Workflow for New Features

## ⚠️ CRITICAL RULE

**NEVER implement directly without first:**
1. Creating a feature document
2. Showing the implementation plan
3. Receiving confirmation

This rule applies ALWAYS, without exception!

---

## Prompt Template for AI (Cursor/Claude)

```
CONTEXT:
- Read docs/implementations/overview.md for project basics

TASK:
[Describe your feature requirement here]

PROCEDURE:
1. Analyze the requirement

2. Create feature document:
   - Use docs/templates/feature-template.md as basis
   - Save under docs/implementations/[feature-name].md

3. Fill out feature document completely:
   - Status: Planned
   - Metadata (Priority, Dependencies)
   - Overview
   - Technical Details
   - Implementation Plan (detailed!)
   - Code Structure
   - Open Questions

4. Update overview document:
   - docs/implementations/overview.md (feature table only!)

5. Show me the feature document for confirmation

6. After my confirmation:
   - Implement according to implementation plan
   - Update status in feature document to "Implemented"
   - Add key interfaces/types to the document

IMPORTANT:
- No implementation without confirmed feature document
- Overview file stays compact (only general concepts + feature list)
- All feature details belong in the feature document

```

### Bug Fix
```
CONTEXT: Read overview + feature doc
Bug: [Feature-Name] - [Problem]
→ Analyze, fix, document
```

### Update Documentation
```
Done. Update feature doc + overview.

## Tips

### ✅ DO's
- Maintain overview cleanly from the start
- Create first feature document especially carefully (as reference)
- Follow AI workflow consistently
- Update documentation parallel to development

### ❌ DON'Ts
- Don't code without feature document
- Don't clutter overview with feature details
- Don't start multiple features simultaneously without documentation
- Don't forget to update status

Use the extended structure:
```

├── implementations/
│   ├── api/
│   │   └── overview.md
│   ├── client/
│   │   └── overview.md
│   └── integration/
└── templates/
    ├── feature-template.md
    └── integration-template.md
```
